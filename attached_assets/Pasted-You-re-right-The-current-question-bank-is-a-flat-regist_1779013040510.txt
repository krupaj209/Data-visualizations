## What's Wrong With the Current Bank

| Problem | Example | Why It Weakens Output |
|---------|---------|----------------------|
| **Questions are generic** | "Which entrance should I head to?" applies to ALL monuments | Doesn't distinguish Colosseum (1 gate, 4 lanes) from Vatican (6 entrances, 2 countries) |
| **No CE-signal depth** | `hasMultipleEntrances: true` is binary | Doesn't capture *how many* entrances, *how different* they are, *what the DRD actually says* about them |

| **No cross-question intelligence** | `weekly_pattern` and `hourly_heatmap` are selected independently | Should be one *timing* decision, not two separate questions |
| **No "so what" layer** | Questions ask *what* data exists, not *why* the visitor cares | Results in charts that show data but don't drive action |
| **Subcategory is too coarse** | "Tickets" covers Eiffel Tower, Vatican, cooking class, F1 | Wildly different visitor needs, same question pool |

## The Redesign: From Question Bank to **Visitor Intent Engine**

Instead of:
```
Subcategory → Questions[] → Charts
```

Use:
```
Visitor Intent → Context Signals → Question Bundle → Chart Deck
```

### Layer 1: Visitor Intents (the "why")

These are universal across all CEs:

| Intent | What the Visitor Needs | Example Question |
|--------|----------------------|------------------|
| **When** | Timing optimization | "When should I arrive to avoid waiting?" |
| **How Long** | Duration planning | "How much time should I budget?" |
| **Which** | Choice optimization | "Which option is best for me?" |
| **What If** | Risk mitigation | "What happens if I'm late / it rains / it's closed?" |
| **How** | Logistics | "How do I get there / get in / get around?" |
| **Why** | Value justification | "Is the premium ticket worth it?" |
| **What** | Preparation | "What do I need to bring / know / book?" |

### Layer 2: Context Signals (the "what makes this CE unique")

These come from DRD + live search + CE metadata:

| Signal | Source | How It Changes Questions |
|--------|--------|-------------------------|
| `queue_complexity` | DRD: describes lane types, security, ticket desk | Simple (1 lane) → skip queue question. Complex (4 lanes + security) → `queue_compare` + `rules_checklist` |
| `accessibility_profile` | DRD: ramps, elevators, cobblestones | Full accessibility → `accessibility_guide`. Partial → warning in `entrance_map`. None → skip entirely |
| `transport_richness` | DRD: metro, bus, walk, taxi, bike | 1 option → skip. 3+ options with tradeoffs → `transit_options` |
| `seasonal_dramatic` | DRD: peak vs off-peak crowd difference | 2x difference → `seasonal_curve`. 10x difference → `seasonal_curve` + `price_curve` + `booking_window` |
| `historical_depth` | DRD: founding date, key events, significance | 3+ turning points → `history_timeline`. 1 date → skip or brief text |
| `spatial_complexity` | DRD: named zones, floors, wings | Simple (1 room) → skip. Complex (3+ zones with different crowds) → `zone_crowd_heatmap` + `floor_plan_flow` |
| `ticket_tier_complexity` | DRD: standard, skip-line, guided, combo, membership | 2 tiers → `ticket_ladder`. 5+ tiers with access differences → `ticket_access_matrix` |
| `group_dynamics` | DRD: family-friendly, solo-traveler, large-group | Family-friendly → `best_for_matrix` with family scores. Business-traveler → time-value focus |
| `weather_sensitivity` | Live search: outdoor, seasonal closure, best months | Outdoor + seasonal → `season_weather_fit`. Indoor + climate-controlled → skip |

### Layer 3: Question Bundles (the "what to generate")

A bundle is **1-3 questions that together answer a visitor intent**. Not isolated charts.

| Intent | Bundle | Questions | When to Use |
|--------|--------|-----------|-------------|
| **When** | Timing Bundle | `weekly_pattern` + `hourly_heatmap` + `booking_window` | DRD shows crowd variability OR sell-out risk |
| **How Long** | Duration Bundle | `duration_stat` + `itinerary_flow` | Fixed runtime → skip. Variable → include |
| **Which** | Choice Bundle | `best_for_matrix` + `compare_zones` + `slot_compare` | 2+ options with material differences |
| **What If** | Risk Bundle | `departure_reliability` + `return_buffer_rank` + `rules_checklist` | Weather cancellation OR strict timing OR strict rules |
| **How** | Logistics Bundle | `entrance_map` + `transit_options` + `rules_checklist` | Complex arrival OR multiple entrances OR strict security |
| **Why** | Value Bundle | `time_value_matrix` + `savings_breakdown` + `ticket_access_matrix` | Premium tier exists AND price gap > 30% |
| **What** | Prep Bundle | `rules_checklist` + `daily_programme` + `booking_window` | Restricted items OR timed events OR advance booking required |

### Layer 4: Page-Type Assembly (the "where this lives")

A page type assembles **2-4 bundles**, not individual questions:

| Page Type | Bundles | Why These |
|-----------|---------|-----------|
| **Plan Your Visit** | Timing + Duration + Logistics + Prep | Answers "when, how long, how do I get in, what do I bring" |
| **Skip the Line** | Value + Timing + Risk | Answers "is it worth it, when does it help most, what if I'm late" |
| **Entrances** | Logistics + Choice + Risk | Answers "which door, which lane, what if something goes wrong" |
| **History** | Duration (story) + Choice (highlights) | Answers "what happened here, what should I see" |
| **Map / Floor Plan** | Logistics + Choice | Answers "where am I going, what should I prioritize" |

## How the Engine Works

```
Input: CE slug + Page type + DRD + Live search results

Step 1: Extract context signals from DRD
  → queue_complexity: "complex" (4 lanes, security, ticket desk)
  → accessibility_profile: "partial" (ramp at main gate, stairs inside)
  → transport_richness: "high" (metro, bus, taxi, walk, bike)
  → historical_depth: "deep" (5+ turning points)
  → spatial_complexity: "simple" (1 arena, no zones)
  → ticket_tier_complexity: "high" (standard, skip-line, guided, combo, membership)

Step 2: Score bundles for this CE
  Timing Bundle:     95/100 (high crowd variability, sell-out risk)
  Duration Bundle:   30/100 (fixed visit, ~2-3 hours)
  Logistics Bundle:  98/100 (complex arrival, multiple lanes, strict security)
  Value Bundle:      90/100 (skip-line saves 60-180 min, price gap 2x)
  Prep Bundle:       85/100 (prohibited items, timed entry, ID required)
  Risk Bundle:       70/100 (strict timing, no re-entry, security delays)

Step 3: Assemble page deck from top bundles
  Plan Your Visit: Timing (95) + Logistics (98) + Prep (85) + Value (90)
  Skip the Line: Value (90) + Timing (95) + Risk (70)
  Entrances: Logistics (98) + Risk (70) + Choice (60)

Step 4: Generate questions within each bundle
  Logistics Bundle → entrance_map (complex, 4 lanes) + transit_options (5 modes) + rules_checklist (strict security)
  Value Bundle → time_value_matrix (6 scenarios) + queue_compare (3 lanes)

Step 5: Generate editorial overlays
  Each bundle gets a narrative headline: "Getting In: The Complete Guide"
  Each question gets a contextual subheadline: "4 lanes, 5 transport modes, 1 strict security check"
```
